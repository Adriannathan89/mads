# MADS v0.6.0 Scoped HTTP and Passport Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make generated controllers, routes, guards, Passport strategies, and JWT requirements consume the core root-module scope while preserving global inspection APIs.

**Architecture:** Add declaration namespaces to common descriptors, derive one `HttpApplicationScope` from the retained core `ModuleGraph`, and use it for route validation and guard preflight. Router registration receives preselected Passport bindings so request-time middleware never reverts to a global strategy lookup.

**Tech Stack:** Rust 2024, Axum 0.8, Tower 0.5, `inventory`, MADS core module scope, Passport/JWT metadata, procedural macros using `syn`/`quote`, and Tokio integration tests.

**Spec:** `docs/superpowers/specs/2026-08-27-v0.6.0-modules-cors-http-runtime-design.md`

## Global Constraints

- Plan 1 must be complete before this plan starts.
- Keep `RouteCatalog`, `GuardCatalog`, and `PassportStrategyCatalog` as complete global inventory APIs.
- Rootless applications must preserve complete-catalog route and Passport behavior.
- Rooted router construction includes only reachable controller/route metadata.
- All selected routes share one conflict domain.
- Strategy visibility is evaluated per guard context and is not transitively re-exported.
- One visible custom `jwt` strategy overrides the built-in fallback; two visible custom candidates fail.
- Same-named strategies in disjoint module contexts may coexist.
- Unreachable HTTP/JWT metadata must not produce bootstrap or configuration requirements.
- No request-time code may redo strategy selection against the global catalog.
- Keep public APIs documented, unsafe code forbidden, and line coverage at least 85%.

pub struct RouterBuildContext<'a> {
