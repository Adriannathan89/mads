# MADS v0.7.0 Integration, Documentation, and Beta Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the complete v0.7 CLI, document its exact behavior, prove process/watcher support on Linux/macOS/Windows, and prepare—not publish—the complete `0.7.0-beta.1` release candidate.

**Architecture:** Plans 1-4 remain the implementation owners. This plan adds black-box command-matrix fixtures, platform CI, current architecture/CLI documentation, examples, release notes, packaging checks, and one evidence-backed beta gate. Stable v0.7 is documented as a later promotion of the same feature set after beta fixes only.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, GitHub Actions Linux/macOS/Windows runners, PostgreSQL 16, Cargo package/MSRV/feature checks, rustdoc, Clippy, cargo-llvm-cov, Markdown, and Git.

**Spec:** `docs/superpowers/specs/2026-09-01-v0.7.0-cli-dev-loop-diagnostics-design.md`

## Global Constraints

- Plans 1-4 must be complete before this plan starts.
- The workspace version remains exactly `0.7.0-beta.1` throughout this plan.
- Beta.1 contains every approved v0.7 command; do not defer an incomplete v0.7 command to a later beta.
- Stable `0.7.0` may contain bug fixes, tests, documentation corrections, and release verification only; no new feature.
- Do not implement v0.8 input validation, expanded HTTP errors, generic typed configuration, compiler diagnostic rewriting, or JSON CLI output.
- Keep `mads foundation` removed and `mads db generate <name>` invalid.
- Document standard `Mads::run::<AppModule>()` as the v0.7 inspection contract and disclose pre-entry user/build-script side effects.
- Document generated migrations as review-required and never auto-applied.
- Cross-platform CI covers CLI process and watcher behavior; real PostgreSQL SQL round trips remain on the PostgreSQL service job.
- Do not push, publish crates, create a tag, or create a GitHub release in this plan.
- Keep public APIs documented, unsafe code forbidden, Rust 1.85, and workspace line coverage at least 85%.

- [ ] **Step 3: Add a dedicated CLI platform matrix to CI**

Add:

```yaml
  cli-platform:
    name: CLI (${{ matrix.os }})
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: clippy, rustfmt
      - uses: Swatinem/rust-cache@v2
      - name: Install libpq (Ubuntu)
        if: runner.os == 'Linux'
        run: sudo apt-get update && sudo apt-get install --yes libpq-dev
      - name: Install libpq (macOS)
        if: runner.os == 'macOS'
        run: |
          brew install libpq
          echo "LIBRARY_PATH=$(brew --prefix libpq)/lib" >> "$GITHUB_ENV"
          echo "PKG_CONFIG_PATH=$(brew --prefix libpq)/lib/pkgconfig" >> "$GITHUB_ENV"
      - name: Install PostgreSQL client (Windows)
        if: runner.os == 'Windows'
        shell: pwsh
        run: |
          choco install postgresql16 --no-progress -y
          $pg = Get-ChildItem 'C:\Program Files\PostgreSQL' -Directory |
            Sort-Object Name -Descending | Select-Object -First 1
          "PQ_LIB_DIR=$($pg.FullName)\lib" | Out-File -FilePath $env:GITHUB_ENV -Append
          "$($pg.FullName)\bin" | Out-File -FilePath $env:GITHUB_PATH -Append
      - name: Test CLI processes and watcher
        run: cargo test --locked -p mads-cli -- --test-threads=1
```

Keep real PostgreSQL ignored tests in the existing Ubuntu service job. Do not
remove the stable, MSRV, coverage, or PostgreSQL jobs.
