# MADS v0.6.0 Facade, Documentation, and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the approved module/run/router API through `mads`, merge the old v0.5.6 roadmap into v0.6.0 documentation, align examples, bump the workspace release, and pass every release gate.

**Architecture:** Keep `mads-core` and `mads-common` as the implementation owners from Plans 1-3; the facade only re-exports their standard surface. Documentation presents `Mads::run::<AppModule>()` as the default and keeps explicit builders for custom values, migrations, lifecycle hooks, native routers, addresses, and configuration sources.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, MADS facade feature matrix, `trybuild`, Cargo consumer fixtures, rustdoc, Clippy, cargo-llvm-cov, Markdown documentation, and Git.

**Spec:** `docs/superpowers/specs/2026-08-27-v0.6.0-modules-cors-http-runtime-design.md`

## Global Constraints

- Plans 1-3 must be complete before this plan starts.
- The standard public source is exactly `Mads::run::<AppModule>().await` with `mads::prelude::*`.
- Export `MadsRunExt` through the standard prelude so trait-method lookup supports that syntax.
- Remove `MadsBuilder` from the standard prelude but keep it public at `mads::core::MadsBuilder` and through inherent `Mads::builder*` functions.
- Keep low-level `build_router`, `configure_router`, `serve`, and `serve_router` public.
- Merge the old v0.5.6 timeline into one v0.6.0 milestone; do not leave forward-looking documents assigning CORS/auto-binding to v0.5.6.
- Do not rewrite shipped v0.5.5 behavior as though it was module-scoped; add supersession notes to historical documents.
- `docs/examples/final_application_clean_architecture.md` uses v0.6.0 module/run behavior and `database.migrate = false`; trait binding, `Inject<dyn Trait>`, and validation remain clearly labeled later-v1 concepts.
- Do not add automatic migration discovery, trait binding, validation, generic typed config, TLS, or third-party auto-configuration.
- Update the workspace version to exactly `0.6.0`; keep Rust version `1.85` and edition `2024`.
- Keep public APIs documented, unsafe code forbidden, and workspace line coverage at least 85%.
