# MADS.rs v0.5.5 Cookies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add strict, redacted Axum request-cookie extraction and checked multi-`Set-Cookie` response composition for MADS and native Axum routes.

**Architecture:** A MADS `CookieJar` newtype validates every raw request cookie instead of inheriting `axum-extra`'s infallible skip-on-error behavior, while retaining the established cookie types and Axum extractor/response composition model. Pending response cookies are validated as a complete batch before delegating header emission, preventing partial `Set-Cookie` output. The jar retains only safe counts in `Debug` and target-name occurrence counts for Plan 4 authentication extraction.

**Tech Stack:** Rust 2024, Rust 1.85.0, Axum 0.8.9, `axum-extra` 0.12.6 `cookie` feature, `cookie` 0.18.1, Tower 0.5.

**Spec:** `docs/superpowers/specs/2026-08-25-v0.5.5-passport-jwt-and-cookies-design.md`

## Global Constraints

- Complete Plan 1 first; compile cookie support only under the `cookies` feature, which implies `http`.
- Expose `Cookie`, `CookieJar`, `Expiration`, `SameSite`, and `cookie::time`.
- Parse every request `Cookie` header and every semicolon-delimited pair; do not silently discard malformed/non-UTF-8 values.
- Ordinary malformed request cookies map to `400 Bad Request` through a typed rejection.
- Duplicate cookie names remain representable for ordinary cookie handling; expose occurrence counts so Passport can reject a duplicated target.
- Support `get`, `iter`, `add`, `remove`, and multiple `Set-Cookie` headers.
- Preserve `Path`, `Domain`, `Max-Age`, `Expires`, `HttpOnly`, `Secure`, and `SameSite` attributes.
- Validate all pending outgoing cookies before changing response headers; invalid output produces no partial `Set-Cookie` emission.
- Reject `SameSite=None` when `Secure` is explicitly false.
- Never show cookie names or values in `Debug`, `Display`, diagnostics, or framework errors.
- Do not add signed/private jars, sessions, CSRF middleware, or JWT-specific behavior in this plan.
- Use `MADS110` for cookie parsing and response-cookie validation.
- Keep native Axum extraction/response composition as an explicit escape hatch.

```rust
//! Strict request-cookie extraction.

use axum::{body::Body, http::{HeaderMap, HeaderValue, Request, header::COOKIE}, routing::get, Router};
use mads_common::CookieJar;
use tower::ServiceExt;

#[test]
fn parses_multiple_headers_and_tracks_duplicate_names() {
    let mut headers = HeaderMap::new();
    headers.append(COOKIE, HeaderValue::from_static("theme=dark; session=one"));
    headers.append(COOKIE, HeaderValue::from_static("session=two; language=en"));
    let jar = CookieJar::from_headers(&headers).unwrap();
    assert_eq!(jar.get("theme").unwrap().value(), "dark");
    assert_eq!(jar.occurrences("session"), 2);
    assert_eq!(jar.iter().count(), 3);
}

#[tokio::test]
async fn malformed_cookie_is_bad_request_instead_of_being_skipped() {
    async fn handler(_: CookieJar) {}
    let app = Router::new().route("/", get(handler));
    let response = app
        .oneshot(
            Request::builder()
                .uri("/")
                .header("cookie", "valid=value; malformed")
                .body(Body::empty())
                .unwrap(),
        )
        .await
        .unwrap();
    assert_eq!(response.status(), 400);
}
```

- [ ] **Step 3: Implement typed redacted cookie errors**

Define:

```rust
#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub enum CookieErrorKind { MalformedRequest, InvalidResponse }

pub struct CookieError {
    kind: CookieErrorKind,
    source: Option<Box<dyn std::error::Error + Send + Sync>>,
}
pub type CookieResult<T> = Result<T, CookieError>;
pub struct CookieRejection(CookieError);
pub const MADS110: mads_core::DiagnosticCode = mads_core::DiagnosticCode::new("MADS110");
```

`CookieError::Display` and `CookieRejection` responses use fixed safe messages only. `CookieRejection::IntoResponse` returns 400 for malformed requests and 500 for invalid response composition. Do not include parser/header/cookie text.

```rust
#[tokio::test]
async fn tuple_response_emits_each_cookie_with_all_attributes() {
    async fn handler(jar: CookieJar) -> (CookieJar, &'static str) {
        let access = Cookie::build(("access", "token-a"))
            .path("/")
            .domain("example.com")
            .http_only(true)
            .secure(true)
            .same_site(SameSite::Strict)
            .max_age(cookie::time::Duration::minutes(15))
            .build();
        let refresh = Cookie::build(("refresh", "token-b"))
            .path("/auth/refresh")
            .expires(cookie::time::OffsetDateTime::now_utc() + cookie::time::Duration::days(7))
            .http_only(true)
            .secure(true)
            .same_site(SameSite::Lax)
            .build();
        (jar.add(access).add(refresh), "ok")
    }
    let app = Router::new().route("/", get(handler));
    let response = app
        .oneshot(Request::builder().uri("/").body(Body::empty()).unwrap())
        .await
        .unwrap();
    let values = response
        .headers()
        .get_all(SET_COOKIE)
        .iter()
        .map(|value| value.to_str().unwrap())
        .collect::<Vec<_>>();
    assert_eq!(values.len(), 2);
    assert!(values.iter().any(|value| {
        value.contains("access=")
            && value.contains("Path=/")
            && value.contains("Domain=example.com")
            && value.contains("HttpOnly")
            && value.contains("Secure")
            && value.contains("SameSite=Strict")
            && value.contains("Max-Age=900")
    }));
    assert!(values.iter().any(|value| {
        value.contains("refresh=")
            && value.contains("Path=/auth/refresh")
            && value.contains("Expires=")
            && value.contains("SameSite=Lax")
    }));
}
```
