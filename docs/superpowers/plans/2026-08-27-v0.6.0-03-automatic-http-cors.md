# MADS v0.6.0 Automatic HTTP and CORS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add conventional configuration loading, scope-aware HTTP server/CORS decisions, application-wide CORS, native router composition, and `Mads::run::<AppModule>()` runtime behavior.

**Architecture:** Represent resolved server and CORS settings as private official auto-configuration outputs stored in the normal application context. Standard run selects automatic listener ownership before core build; low-level builders remain explicit and report the automatic server as overridden. Raw router construction stays separate from final application-wide layer configuration.

**Tech Stack:** Rust 2024, Axum 0.8.9, Tokio, Tower 0.5, Tower HTTP 0.6 CORS, MADS configuration/auto-configuration, and in-process HTTP service tests.

**Spec:** `docs/superpowers/specs/2026-08-27-v0.6.0-modules-cors-http-runtime-design.md`

## Global Constraints

- Plans 1 and 2 must be complete before this plan starts.
- `Mads::run` loads only optional `.env`, optional `mads.toml`, then `MADS_*` from the current working directory.
- Dotenv remains interpolation-only and never mutates process state.
- Present malformed/unreadable files fail; absent files are allowed.
- Automatic server defaults are host `127.0.0.1` and port `3000`; automatic port zero is invalid.
- Explicit `serve`/`serve_router` addresses ignore server host/port and may use port zero.
- Standard run requires at least one reachable managed route; native-only routers remain low-level.
- CORS is disabled when `[server.cors]` is absent and is included in the existing `http` feature.
- CORS wildcard is scalar `"*"`; explicit values are arrays; methods never accept wildcard.
- Credentialed CORS rejects all wildcard origin/header modes before Tower layer construction.
- CORS is the outermost layer after generated/native merge and is not authorization or CSRF protection.
- Preflight/configuration/router validation happens before lifecycle startup; post-start bind failures trigger shutdown.
- Reports, diagnostics, and `Debug` output never retain resolved host, port, origin, method, or header values.
- Keep public APIs documented, unsafe code forbidden, and line coverage at least 85%.

- [ ] **Step 4: Implement exact two-shape parsing**

Define private parsed forms:

```rust
enum CorsValues<T> {
    Any,
    List(Vec<T>),
}

pub(crate) struct CorsPlan {
    origins: CorsValues<HeaderValue>,
    methods: Vec<Method>,
    allowed_headers: CorsValues<HeaderName>,
    exposed_headers: CorsValues<HeaderName>,
    credentials: bool,
    max_age: Option<Duration>,
}
```

For wildcard-capable keys, accept `config.get(key) == Some("*")` or
`config.get_string_array(key)`. Reject every other scalar and reject `"*"`
inside arrays. `methods` accepts only a nonempty string array.

Validate origins by parsing `http::Uri` and requiring:

```rust
matches!(uri.scheme_str(), Some("http" | "https"))
    && uri.authority().is_some()
    && uri.path_and_query().is_none()
    && !raw.contains('@')
    && !raw.eq_ignore_ascii_case("null")
```

Require the raw value to be a valid `HeaderValue`. Normalize methods to
uppercase before `Method::from_bytes`, and deduplicate in first-seen order.
Parse headers with `HeaderName::from_bytes` and deduplicate case-insensitively.
Parse booleans as exactly `true`/`false` and max age as `u64`.

Reject `credentials = true` with `CorsValues::Any` in origins, allowed headers,
or exposed headers before calling Tower HTTP. Custom `Debug` prints counts,
boolean presence, and `"[REDACTED]"`, never values.

- [ ] **Step 5: Build the Tower HTTP layer from validated values**

Implement:

```rust
pub(crate) fn layer(&self) -> CorsLayer {
    let mut layer = CorsLayer::new()
        .allow_methods(self.methods.clone())
        .allow_credentials(self.credentials);

    layer = match &self.origins {
        CorsValues::Any => layer.allow_origin(Any),
        CorsValues::List(values) => layer.allow_origin(values.clone()),
    };
    layer = match &self.allowed_headers {
        CorsValues::Any => layer.allow_headers(Any),
        CorsValues::List(values) => layer.allow_headers(values.clone()),
    };
    layer = match &self.exposed_headers {
        CorsValues::Any => layer.expose_headers(Any),
        CorsValues::List(values) => layer.expose_headers(values.clone()),
    };
    if let Some(max_age) = self.max_age {
        layer = layer.max_age(max_age);
    }
    layer
}
```

Use the precise `tower_http::cors::{AllowHeaders, AllowOrigin, ExposeHeaders}`
conversion required by Tower HTTP 0.6 if direct `Vec` conversion is not
accepted; do not replace exact lists with predicate closures.

- [ ] **Step 3: Implement the public extension trait**

Add documented API:

```rust
pub trait MadsRunExt {
    fn run<M>() -> impl Future<Output = Result<(), HttpRuntimeError>> + Send
    where
        M: mads_core::Module;
}

impl MadsRunExt for Mads {
    fn run<M>() -> impl Future<Output = Result<(), HttpRuntimeError>> + Send
    where
        M: mads_core::Module,
    {
        async move {
            let root = std::env::current_dir().map_err(config_directory_error)?;
            let prepared = prepare_standard_run::<M>(&root).await?;
            serve_prepared(prepared, TcpListener::bind, shutdown_signal()).await
        }
    }
}
```
