# MADS.rs v0.4.0 Diesel-first Persistence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. One Executor run completes exactly one top-level task and stops for review.

**Goal:** Add explicit, lifecycle-managed PostgreSQL persistence with native Diesel queries, migrations, CLI commands, and a real CRUD proof for MADS.rs v0.4.0.

**Architecture:** `mads-common` owns a cloneable `Database` backed by `deadpool-diesel`, runs synchronous Diesel closures on blocking workers, and installs the database as an explicit existing-graph provider plus lifecycle hook. `mads-core` gains generic scalar TOML, optional dotenv variable loading, and exact whole-value interpolation without database semantics or process-environment mutation; database auto-configuration remains deferred to v0.5. Embedded migrations serve applications, file migrations serve the CLI, and PostgreSQL integration tests exercise the same public facade used by consumers.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, Tokio 1, Diesel `=2.2.12`, `diesel_migrations =2.2.0`, `deadpool-diesel =0.6.1`, PostgreSQL 16, Axum 0.8, TOML `=0.8.23`, dotenvy `=0.15.7`, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-08-22-v0.4-diesel-persistence.md`

## Global Constraints

- Keep the workspace on Rust edition 2024 and `rust-version = "1.85"`.
- Pin `diesel = "=2.2.12"`, `diesel_migrations = "=2.2.0"`, `deadpool-diesel = "=0.6.1"`, `toml = "=0.8.23"`, and `dotenvy = "=0.15.7"`; do not resolve Diesel 2.3 because it requires Rust 1.86.
- Keep `mads-core` free of Diesel, `deadpool-diesel`, PostgreSQL, migration, HTTP, `mads-common`, and `mads-extra` normal dependencies.
- PostgreSQL is the only v0.4 backend; do not generalize the public API to unimplemented backends.
- Keep database provisioning explicit through `MadsBuilderDatabaseExt`; do not add v0.5 requirement detection, auto-configuration, or back-off.
- Never include a loaded configuration value, database URL, or interpolated secret in MADS-owned `Debug`, `Display`, diagnostics, CLI output, or authored assertion messages.
- Parse dotenv files into a temporary interpolation map; never call `set_var` or otherwise mutate the process environment. Real Unicode process variables override dotenv values.
- Run every Diesel closure on `deadpool-diesel::Connection::interact`; never execute synchronous Diesel work directly on a Tokio worker.
- Preserve native Diesel and Diesel migration escape hatches through facade re-exports.
- Preserve all v0.3 HTTP routing semantics, core-only builds, renamed-dependency builds, missing-doc denial, unsafe-code prohibition, and the 85% line-coverage gate.
- Follow red-green-refactor for every task: observe the focused test fail before adding the minimal implementation.
- Use concise Conventional Commit subjects shown in each task if the Executor is authorized to commit; otherwise leave changes staged or uncommitted for the maintainer.
