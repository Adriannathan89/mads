# MADS v0.7.0 CLI, Cargo Resolution, and Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the v0.7 CLI grammar and Cargo project model, remove `mads foundation`, and make `mads run` directly build and execute a single MADS application with optional Cargo selectors and forwarded arguments.

**Architecture:** Keep the CLI parser dependency-light and model Cargo selection explicitly with `cargo_metadata`. Resolve one package/binary using Cargo's current-package, `default-run`, and single-binary rules, build it through Cargo JSON messages, then execute the exact emitted artifact. Database commands reuse the same package-root selection without changing their configuration chain.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, Tokio process/I/O support, `cargo_metadata` 0.19.2, `semver` 1.0.28, Serde JSON, existing MADS diagnostics/database runtime, `assert_cmd`, and Cargo fixture projects.

**Spec:** `docs/superpowers/specs/2026-09-01-v0.7.0-cli-dev-loop-diagnostics-design.md`

## Global Constraints

- This is Plan 1 of 5 and has no implementation-plan prerequisite.
- Set the workspace development version to exactly `0.7.0-beta.1`; stable v0.7 adds no features later.
- A project with one current package and one binary must work with plain `mads run`.
- Preserve Cargo-native `--package`/`-p`, `--bin`, `package.default-run`, and ambiguity behavior.
- Forward every argument after `--` byte-for-byte as an `OsString`; never parse application arguments.
- Keep command syntax failures at exit 2 and CLI operational failures at exit 1.
- Once the application starts, preserve its ordinary numeric exit status.
- Keep the existing database configuration order and redaction behavior.
- Remove `mads foundation`; do not leave an alias.
- Do not add input validation, JSON CLI output, HMR, or an external Cargo/CLI executable dependency.
- Keep `#![deny(missing_docs)]`, `#![forbid(unsafe_code)]`, Rust 1.85, and the 85% line-coverage gate.
