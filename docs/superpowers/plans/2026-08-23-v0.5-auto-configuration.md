# MADS.rs v0.5 Auto-Configuration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic, inspectable official auto-configuration engine that supplies a default Diesel `Database` when the complete provider catalog requires it and no application provider overrides it.

**Architecture:** `mads-core` evaluates inventory-registered official descriptors before provider-graph validation, adds virtual satisfactions for active defaults, and applies those defaults only after the combined analysis succeeds. `mads-common` contributes the first descriptor, owns all Diesel conditions and provisioning, and registers a database infrastructure hook that surrounds application lifecycle hooks.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, `inventory`, Tokio, Diesel 2.2.12, `diesel_migrations` 2.2.0, `deadpool-diesel` 0.6.1, PostgreSQL 16, `trybuild`, `cargo_metadata`, `cargo-llvm-cov`.

**Spec:** `docs/superpowers/specs/2026-08-23-v0.5-auto-configuration-design.md`

## Global Constraints

- The workspace remains Rust edition 2024 with MSRV Rust 1.85.0.
- `mads-core` must have no normal dependency on Diesel, `deadpool-diesel`, `diesel_migrations`, PostgreSQL client libraries, Axum, or `mads-common`.
- PostgreSQL remains the sole database backend.
- Keep Diesel pinned to `=2.2.12`, `diesel_migrations` to `=2.2.0`, and `deadpool-diesel` to `=0.6.1`.
- Keep `#![forbid(unsafe_code)]`, fully document public APIs, and satisfy workspace `clippy::all = "deny"`.
- Configuration loading remains explicit; do not add file/environment loading to `Mads::builder()`.
- Public analysis must invoke no provider constructor, apply callback, pool constructor, connection, migration, or lifecycle hook.
- Reports and diagnostics must never retain or print resolved configuration values or database URLs.
- Auto-configuration registration remains document-hidden and reserved for official MADS crates.
- Evaluate the complete provider catalog in one pass; do not add module scoping, chained activation, priority selection, or opt-out controls.
- Preserve existing explicit database bootstrap, database CLI output/exit codes, HTTP behavior, and database error classification.
- Do not generate migration files or proactively inspect pending migrations when `database.migrate = false`.
- Infrastructure hooks start before application hooks; shutdown and rollback reverse successful startup order.
- HTTP auto-binding remains v0.5.5, modules v0.6, detailed configuration provenance v0.7, and `mads doctor` v0.8.
- Preserve PostgreSQL 16 CI coverage and the 85% line-coverage gate.

## File Structure

```text
crates/mads-core/src/auto_configuration/mod.rs
    Collect official descriptors and expose focused report types internally.

crates/mads-core/src/auto_configuration/report.rs
    Own public status, reason-code, requirement, configuration-evidence, and
    report records.

crates/mads-core/src/auto_configuration/descriptor.rs
    Own the document-hidden descriptor, read-only contexts, evaluation result,
    contribution, and type-erased integration-input registry.

crates/mads-core/src/auto_configuration/analysis.rs
    Validate/sort descriptors, evaluate conditions, detect conflicts, and
    return reports, virtual satisfactions, covered missing types, selected
    descriptors, and source-preserving failures.

crates/mads-core/src/builder.rs
    Combine auto-configuration and graph analysis, apply selected defaults,
    execute the ordinary construction plan, and retain reports in Mads.

crates/mads-core/src/graph/model.rs
    Represent AutoConfiguration/AutoConfigured nodes and retain reports in
    GraphAnalysis.

crates/mads-core/src/graph/analysis.rs
    Accept virtual satisfactions and covered missing types while preserving
    ordinary graph diagnostics.

crates/mads-core/src/lifecycle.rs
    Store infrastructure/application hook ordering metadata and execute one
    canonical startup sequence with exact reverse rollback/shutdown.

crates/mads-common/src/database/auto_configuration.rs
    Register mads.common.database.diesel, evaluate database conditions, apply
    the lazy pool, and register one embedded migration input.

crates/mads-common/src/database/lifecycle.rs
    Share DatabaseLifecycle between explicit and automatic provisioning and
    preserve MADS100 runtime error sources.

crates/mads-common/tests/database_auto_configuration*.rs
    Isolate complete-catalog condition fixtures so skip, active, static
    override, and ambiguous override cases cannot contaminate one inventory.

crates/mads/tests/postgres_crud.rs
    Prove public-facade zero-database-bootstrap CRUD and explicit graph/report
    inspection.
```

Files not listed above retain their current ownership. In particular, database
configuration stays in `database/config.rs`, pool construction in
`database/pool.rs`, migration execution in `database/migration.rs`, and error
classification in `database/error.rs`.

