# MADS v0.6.0 Core Module Scope Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn core `#[module]` metadata into a deterministic root-scoped provider graph with namespace ownership, direct-import visibility, and retained inspection.

**Architecture:** Extend existing descriptors with additive namespace/import metadata, then build a framework-neutral `ModuleGraph` before provider and auto-configuration analysis. Rooted builders select owned providers plus their legal dependency closure; rootless builders continue passing the complete catalog through the existing analyzer.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, `inventory`, `TypeId`, procedural macros using `syn`/`quote`, Tokio tests, and the existing MADS graph/diagnostic model.

**Spec:** `docs/superpowers/specs/2026-08-27-v0.6.0-modules-cors-http-runtime-design.md`

## Global Constraints

- Keep `mads-core` framework-neutral: no Axum, HTTP, Tower, Passport, database, or CORS dependencies.
- Preserve every existing `ProviderDescriptor::new` and `ModuleDescriptor::new` caller through additive metadata methods.
- Preserve rootless `MadsBuilder` complete-catalog behavior exactly.
- A rooted build activates every provider owned by a reachable module and only required unowned providers.
- Cross-module access requires a direct import and unrestricted `ProviderVisibility::Public`.
- Restricted Rust visibility remains represented as `ProviderVisibility::Private`.
- Unowned dependency chains retain their originating module context.
- Deduplicate construction by `TypeId`; never depend on inventory or hash iteration order.
- Reports and diagnostics must not contain configuration values.
- Keep `#![deny(missing_docs)]`, `#![forbid(unsafe_code)]`, and the 85% line-coverage gate.

- [ ] **Step 4: Implement deterministic traversal and diagnostics**

Allocate `MADS008` for invalid module graphs. Implement a declaration-order DFS
with a recursion stack and a `TypeId`-keyed visited set. The algorithm must:

```rust
fn visit(module: TypeId, state: &mut BuildState<'_>) -> Result<()> {
    if let Some(cycle_start) = state.stack.iter().position(|id| *id == module) {
        return Err(module_cycle_error(&state.stack[cycle_start..], module));
    }
    if !state.visited.insert(module) {
        return Ok(());
    }

    let descriptor = state.require_descriptor(module)?;
    state.validate_unique_namespace(descriptor)?;
    let node = state.push_node(descriptor)?;
    state.stack.push(module);
    state.validate_duplicate_direct_imports(descriptor)?;
    for import in descriptor.imports() {
        let imported = state.require_descriptor(import.type_id())?;
        let imported_node = state.ensure_node(imported)?;
        state.push_edge(node, imported_node);
        visit(import.type_id(), state)?;
    }
    state.stack.pop();
    Ok(())
}
```

Do not expose the test helper as stable API; re-export it only from
`__private` for integration coverage. Export the immutable model normally.
